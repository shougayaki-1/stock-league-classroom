# 資料（AIへのファイルアップロード）設計仕様

**日付:** 2026-08-09
**対象:** Phase E(AI・教材作成強化)のサブプロジェクト4 — 資料
**正本:** `docs/superpowers/specs/2026-08-05-integrated-platform-spec.md` §15.3・§15.4・§15.5（資料関連の記述）。矛盾する場合は正本を優先し、本仕様側の誤りとして扱う。

## 背景・位置づけ

この機能は単体では使い道が薄く、既存の「AI Lesson Studioコア」（`docs/superpowers/specs/2026-08-09-ai-lesson-studio-core-design.md`、実装中）の入力の質を上げるための付属機能である。AI Lesson Studioコアは教師のテキスト入力（テーマ・目標）のみをAIへ渡すが、本機能により教師は参考資料（教科書のPDF等）をアップロードし、その内容を踏まえた授業案をAIに作らせられるようになる。

**スコープ判断（ユーザー承認済み）:**
- 対応ファイル形式は**テキスト型PDFとプレーンテキストのみ**。スキャン画像・写真・図表画像は対象外（テキスト抽出できずエラーになる）。画像OCRには別途Google Cloud Vision等の外部プロバイダ選定が必要になり、AI Lesson Studioコアの`LlmProvider`と同じ「未選定」問題を抱えるため、本仕様のv1では扱わない。
- テキスト抽出まで含める（AIへ実際に資料の内容を反映するところまでが本仕様のゴール）。

**この判断の前提となる事実:** `firebase.json`にStorage関連の設定が一切存在しない——このプロジェクトはFirebase Storageを未使用である。本機能の実装には、Firebase Storageをこのプロジェクトで新規に有効化する外部作業（Firebase Consoleでの有効化）が必要になる。これはPhase A完了条件で保留されていた「Blaze/予算アラート外部ゲート」と同種の、コード実装だけでは完結しない外部依存として扱う（実装は先行して進めてよいが、実際にStorageへ書き込みが発生する動作確認にはこの外部有効化が必要）。

## アーキテクチャ

### ファイル保存

Firebase Storage（新規導入）。パス: `orgs/{orgId}/materials/{materialId}/{fileName}`。

### テキスト抽出

アップロード直後、**クライアント側**（ブラウザ）で`pdfjs-dist`を使いPDF内のテキストを抽出する。サーバー側でStorageファイルを読み直す往復を避けるため。プレーンテキストファイルはそのままテキストとして読み込む。

抽出したテキストは`lessonTemplates/{templateId}/materials/{materialId}`ドキュメント（新規Firestoreサブコレクション）へ保存する。元ファイルはStorageに残すが、**AIへ渡すのは抽出済みテキストのみ**——Storageの生ファイルはAI呼び出し経路には一切触れさせない。

### AIへの受け渡し

AI Lesson Studioコアの`generateLessonDraftCallable`（実装中）を拡張し、教師が選択した資料の抽出テキストをプロンプトへ追加できるようにする。統合仕様書§15.3「送信前に教師が対象内容を確認する」を満たすため、AI呼び出し前に「この資料の内容をAIへ送信します」という確認UIを挟む（自動送信しない）。

### PIIフィルタとの関係

AI Lesson Studioコアの`piiFilter.ts`はキー名ベースの構造化データ検査であり、資料から抽出した自由記述テキストには機械的に適用できない。ここは自動フィルタではなく「教師が資料を選んでアップロードし、送信前に確認する」という人手のゲートで担保する。統合仕様書§15.3が「送信前に教師が対象内容を確認する」と明記していることと整合する設計判断であり、既存の自動PIIフィルタが自由記述テキストまでカバーしないことの意図的な既知の限界として明記する。

### 組織制御・利用枠

`organizations/{orgId}`ドキュメントへ`materialsUploadEnabled: boolean`トグルを追加（既定`false`）。統合仕様書§15.4「ファイルアップロード」項目に対応する。ファイルサイズ・ページ数の上限（§15.5「資料ページ数・容量上限」）はアップロード時にクライアント側でハード制約として検証する（初期値: 10MB・50ページ、AI Lesson Studioコアと同様に`tuningConstants.ts`パターンで1箇所に定数化する）。

## データフロー

```
[教師: 教材テンプレート編集画面] --ファイル選択(PDF/txt)--> クライアント側でファイルサイズ・ページ数を検証
  --> Firebase Storageへアップロード --> pdfjs-distでテキスト抽出（クライアント側）
  --> lessonTemplates/{templateId}/materials/{materialId} へ抽出テキスト・ファイル名・アップロード日時を保存
--> [AI提案カード選択時] --> 資料一覧から使う資料をチェックボックスで選択
  --> 「この資料の内容をAIへ送信します」確認 --> generateLessonDraftCallable（資料テキストをプロンプトへ追加）
```

## エラー処理

- `materialsUploadEnabled`が`false`の場合: 資料アップロードUI自体を表示しない。
- ファイルサイズ・ページ数の上限超過: アップロード前にクライアント側で拒否し、上限値を明示したメッセージを表示する。
- PDF内にテキストが存在しない場合（スキャン画像のみのPDF等）: 「このファイルからテキストを抽出できませんでした」と表示し、アップロード自体は行わない（抽出テキストが空のまま資料として保存しない）。
- Storageアップロード失敗: エラーメッセージを表示し、再試行を促す。

## テスト方針

- PDFテキスト抽出関数: `pdfjs-dist`を使った抽出処理を、テキスト型PDFのフィクスチャ（またはモック）で検証する。
- ファイルサイズ・ページ数の検証関数: 上限内/超過それぞれで正しく合否判定することを純粋関数テストで検証する。
- 資料一覧・選択UI: アップロード済み資料が一覧表示され、選択した資料のIDが`generateLessonDraftCallable`呼び出しへ正しく渡ることを検証する。
- `generateLessonDraftCallable`の拡張: 資料テキストがプロンプトへ追加されることを検証する。
- `storage.rules`: 他組織のファイルを読み書きできないことを検証するルールテスト（既存の`test:rules`と同じ形式）。
