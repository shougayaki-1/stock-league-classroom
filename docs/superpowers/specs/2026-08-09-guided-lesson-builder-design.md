# Guided Lesson Builder 設計仕様

**日付:** 2026-08-09
**対象:** Phase E(AI・教材作成強化)のサブプロジェクト1 — Guided Lesson Builder
**正本:** `docs/superpowers/specs/2026-08-05-integrated-platform-spec.md` §14（授業作成）。矛盾する場合は正本を優先し、本仕様側の誤りとして扱う。

## 背景・スコープ判断

統合仕様書 §25 は Phase E に「Guided Builder」「AI Studio」「資料」「試運転」「スライド自動生成」の5項目を挙げている。これらは相互にかなり独立したサブシステムであり、1つの仕様書にまとめるとスコープが大きくなりすぎるため、サブプロジェクトへ分解した。本仕様は最初のサブプロジェクトである **Guided Lesson Builder**（§14.1〜§14.4、AIを使わないルールベースの選択式授業作成）のみを対象とする。AI Lesson Studio（§15）・試運転モード・スライド自動生成は別仕様として後日作成する。

**前提として確認した現状:** 教師向けの教材作成UIはPhase A〜Dを通じて一切実装されていない。存在するのは `LessonTemplate`/`LessonVersion` のFirestoreデータモデルと、`createLessonTemplate`/`saveDraft`/`publishLessonVersion`（`src/lib/lessonTemplates/`）というクライアント側の永続化関数のみである。教師がこれらに到達するためのルート・ホーム画面も存在しない。したがって本仕様は、この分野で最初の教師向けUIをゼロから設計するものである。

**スコープに含める:**
- 教師ホーム画面（教材一覧・新規作成の入り口）
- Guided Builderウィザード（学習目標のフレーミングによる科目選択 → 質問ステップ → 3案生成 → 選択 → 最終確認）
- フルエディタ（主要配列のCRUDまで — 企業/人物、資産・保険・イベント定義の名称やスカラーフィールド）
- 社会科・家庭科の両方を同時に対象とする

**スコープに含めない（明示的な将来課題）:**
- AI Lesson Studio（§15）
- 試運転モード（PROVISIONAL定数の設定画面）
- スライド自動生成
- 保険の内部リスク係数・イベント発生確率・需給感度などの内部パラメータ調整（Task 1〜9で「教師には計算式より影響の強さを見せる」と位置づけられた係数群 — JSONインポート/エクスポート等の別手段に委ねる）
- 複数教師によるリアルタイム共同編集（§16.3で「初期は必須にしない」と明記）

## アーキテクチャ

アプローチとして、科目非依存の「共有ウィザードエンジン」「共有エディタシェル」を作り、科目固有のロジック（質問セット・3案プリセットテーブル・配列エディタ）をプラグインとして差し込む構成を採る。理由は以下の2点:

1. `LessonContent` は既に `subject` で判別され、`SocialStudiesMarketContent`/`HomeEconomicsContent` がそれぞれ独立パッケージとして型レベルで分離されている既存パターンと自然に整合する。
2. 将来のAI Lesson Studioが同じ「`LessonContent` ドラフトを組み立てて `createLessonTemplate`/`saveDraft` へ渡す」パイプラインを再利用できる。

### ルート構成

```
/teacher/templates                    — 教材一覧（既存テンプレート一覧 + 新規作成ボタン）
/teacher/templates/new                — 学習目標選択 → Guided Builderウィザード
/teacher/templates/:templateId/edit   — フルエディタ（ウィザード完了後、または一覧から既存教材を選択）
```

### コンポーネント構成

```
src/components/teacher/templates/
  TemplateListPage.tsx              — 一覧+新規作成入り口
  GuidedBuilderWizard.tsx           — 汎用ステップエンジン（進捗表示・戻る/次へ・状態保持）
  wizardSteps/
    LearningGoalSelectStep.tsx      — 学習目標のフレーミングによる科目選択（共通、詳細は下記）
    socialStudies/QuestionSteps.tsx — §14.1共通項目 + §14.2質問群
    homeEconomics/QuestionSteps.tsx — §14.1共通項目 + §14.3質問群
  TemplateOverviewPage.tsx          — §14.4の最終確認（共通レイアウト、内容は科目プラグイン差し込み）
  TemplateEditorPage.tsx            — フルエディタのシェル（共通: タイトル・保存・版発行）
  editors/
    socialStudies/                  — 企業一覧・ニュース項目CRUD等
    homeEconomics/                  — 担当プロフィール一覧・資産/保険/イベント定義CRUD等

src/lib/lessonTemplates/
  guidedBuilderPresets.ts           — 科目ごとの「簡易/標準/発展」固定プリセットテーブル（新規）
  （既存の createLessonTemplate / saveDraft / publishLessonVersion をそのまま利用、新規Callableは不要）
```

質問ウィジェットは既存の `@stock-league/lesson-inputs`（`SingleChoiceInput`/`NumberInput` 等）をそのまま再利用し、Guided Builder専用の新規ウィジェット型は追加しない。

## Guided Builderウィザードのフロー

### Step 1: 学習目標のフレーミングによる科目選択

「今回の授業で何を学ばせたいですか？」という問いかけで、2枚のカードを提示する。

- **「市場のしくみ・投資判断を学ばせたい」** — 企業の業績・ニュース・需給を見て売買を判断する社会科市場シミュレーション（内部的に `subject: 'SOCIAL_STUDIES'`）
- **「将来に向けた資産形成・生活設計を学ばせたい」** — 家計のプロフィールを担当し、保険・住宅・資産配分・ライフイベントに対応する家庭科生活設計シミュレーション（内部的に `subject: 'HOME_ECONOMICS'`）

各カードには一言説明とアイコンを添える。「社会科」「家庭科」という科目名はカード内の小さな補足ラベルとして添える程度に留め、選択の主眼は学習目標に置く。

### Step 2〜N: 科目別の質問ステップ

共通（§14.1）: 主な学習目標・授業時間・生徒数・端末環境・個人/チーム・資料読解の深さ・テーマ・難易度

- 社会科（§14.2追加）: 企業数・決算を使うか・不確実性を扱うか・情報/需給の重み・常時市場の時間・予想チェックポイント・評価の重点
- 家庭科（§14.3追加）: 人生段階・共通条件か人物比較か・1年/5年・扱う資産/保険/住宅・イベントの公開方法・評価重点

### Step N+1: 3案生成

回答一式を `guidedBuilderPresets.ts` の固定マッピングテーブルに通し、3つの `LessonContent` ドラフト（簡易案・標準案・発展案）を生成する。差分は主にスカラー値（企業数・ラウンド年数等）と、事前定義した「小/中/大」規模の企業・人物配列プリセットの選択。AIは使用しない。教師は3案をカード形式で比較し1つを選択する。

### Step N+2: §14.4最終確認ページ

選択した案の `LessonContent` を人間可読なサマリー（目標・時間・流れ・企業/人物・情報/イベント・生徒操作・教室表示・評価・注意事項）で表示する。タイトル・説明文はここでインライン編集可能。

- 「この内容で作成」→ `createLessonTemplate` 呼び出し → 下書き保存 → フルエディタへ遷移
- 「詳細を編集する」→ 同じく `createLessonTemplate` を呼んでからフルエディタへ遷移（詳細編集も下書きに対して行うため、先に下書きを作成する必要がある）

### 状態管理

ウィザードの回答は `GuidedBuilderWizard` のローカルstateのみで保持し、Firestoreへの書き込みは §14.4確認ページでの確定操作（`createLessonTemplate` 呼び出し）まで発生させない。これにより、ウィザードを離脱した場合に空の下書きが量産されることを避ける。§16.1「通常編集は下書きへ自動保存」はフルエディタ側の責務とし、ウィザード自体は未保存の使い捨て状態として扱う。

## フルエディタ（主要配列のCRUDまで）

### 共通シェル（`TemplateEditorPage.tsx`）

- ヘッダー: タイトル・説明文の編集、保存状態表示（下書き自動保存 / 未保存の変更あり）
- タブ構成: 「基本情報」「主要な一覧」「評価の重み」の3タブ（科目共通の構造）
- フッター: 「下書き保存」（既存 `saveDraft`） / 「この内容で版を発行する」（既存 `publishLessonVersion`、公開後は不変になる旨を確認ダイアログで警告）

### 科目別「主要な一覧」タブ

- 社会科: `SimulatedCompany[]`（企業）の一覧 — 追加/削除/名称・業種・規模区分・初期株価などスカラーフィールドの編集。`InformationItem[]`（ニュース項目）も同タブで簡易CRUD。
- 家庭科: `HouseholdProfile[]`（担当プロフィール）の一覧 — 追加/削除/年齢・世帯収入・生活費等のスカラーフィールド編集。`AssetPosition[]`/`InsuranceProduct[]`/`LifeEventDefinition[]` も同タブで簡易CRUD（名称・型・金額系スカラーのみ）。

### バリデーション

保存・発行のたびに、既存の `validateHomeEconomicsContent`（家庭科）および社会科側の同等バリデーション関数をクライアント側で先に呼び、エラーがあれば発行操作をブロックして該当タブへ誘導する。サーバー側の `createLessonRun` 時バリデーションは最終防衛線として現状のまま維持する（本仕様では変更しない）。

## データフロー

```
[教師ホーム] --新規作成--> [Step1: 学習目標選択] --> [質問ステップ] --> [3案生成・選択]
    --> [§14.4確認ページ] --「この内容で作成」--> createLessonTemplate --> [フルエディタ] --編集/保存--> saveDraft
                                                                                    --版を発行--> publishLessonVersion
[教師ホーム] --既存教材を選ぶ--> [フルエディタ]（以降同じ）
```

## エラー処理

- ウィザード離脱時（ブラウザバック等）: 未保存であることを明示するのみ。自動保存はしない（前述の通り意図的な設計）。
- フルエディタの自動保存失敗: 既存の `saveDraft` のエラーを画面上部にトースト表示し、次回保存操作までローカル編集内容は保持する（データ損失を避ける）。
- 版発行のバリデーション失敗: クライアント側バリデーションで該当タブ・フィールドへスクロールし、日本語エラーメッセージを表示する。

## テスト方針

- `guidedBuilderPresets.ts`: 各回答パターン → 3案の期待される `LessonContent` 差分を検証する純粋関数テスト。
- ウィザードステップ遷移: React Testing Libraryで質問への回答 → 次へ進む → 戻るの状態保持を検証。
- フルエディタの主要配列CRUD: 追加・削除・編集が正しく `LessonContent` へ反映されること、既存バリデーション関数と組み合わせたエラー表示を検証。
- 受け入れテスト観点: 「ウィザードで3案から選択 → 確認 → 作成 → フルエディタで人物/企業を1件追加 → 版発行 → `LessonRun` 作成に使える」という一連のフローを1本のテストで通す（Phase Dの `household-lifecycle.acceptance.test.ts` と同様の位置づけ）。
