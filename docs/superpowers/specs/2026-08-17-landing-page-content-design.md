# ランディングページ（root `/`）コンテンツ整備 設計

## 背景・目的

現在の `/`（`LandingPage`, `src/App.tsx:104-115`）は、ナビゲーション・1枚のクロージングセクション・フッターのみで構成されており、サービスが何であるかを説明するセクションが存在しない。README や `/about` にはサービス概要があるが、初見の教師が最初に着地する root ページ自体には要約が載っていない。

このドキュメントは、root ページのコンテンツ（セクション構成・コピー・使用する実画面）を確定し、後続の実装計画（`writing-plans`）に渡すための設計である。

**目的の優先順位**（ユーザー確認済み）:
1. サービス理解の促進 — 「Stock League Classroom とは何か」を初見の教師にわかりやすく伝える
2. 問い合わせ・興味喚起 — 準備中フェーズなので、興味を持った教師を `/about` や問い合わせへ誘導する
3. 信頼性のアピール — 安全設計・無償提供・データを守る設計思想を伝える

## スコープ

**含む**:
- root ページ（`LandingPage` コンポーネント）のセクション構成とコピーの刷新
- 実装済み教師向け画面（授業作成ウィザード、教材一覧・編集画面）のスクリーンショットを使った「実際の画面」セクション
- 既存の nav / footer は維持し、中間セクションを新設・置換

**含まない**:
- 授業機能（学習セッション・売買・結果画面）のUI自体の実装（Phase Aスコープ外、既に他の設計書で管理）
- `/about` `/guide` `/terms` `/privacy` `/contact` の内容変更（既存のまま）
- 新しい画像素材の作成・発注（`hero.png` は不使用と確定。イラスト等は追加しない）
- 多言語対応（既存同様、日本語のみ）

## トーン&ボイス

- 既存の about/terms/privacy ページと同じ、安心・丁寧な行政・教育機関向けトーンを基調とする
- 見出し・キャッチコピー部分のみ、既存のクロージング文言（「まもなく教室に市場をひらけます。」）と同じ温度感で、少しワクワク感を出す
- 「準備中」であることは隠さず、ヒーロー直後で正直に明示する（期待値を適正化する）

## セクション構成

### 1. ヘッダー（既存維持・変更なし）

`Stock League Classroom` ロゴ＋ナビ（使い方 / 特徴 / 詳しく見る）。既存の `landing-nav` をそのまま使う。

### 2. ヒーローセクション（新規）

root 直下、ヘッダー直後に新設する。

- バッジ: 「教室向け 投資・生活設計シミュレーター」
- 見出し（h1）: 「教室に、市場をひらこう。」
- サブ見出し: 「生徒が情報を読み、判断し、結果から学ぶ。社会科・家庭科で使える、サーバーが進行を守る授業シミュレーターです。」
- 準備中バッジ（Alert相当、控えめな色）: 「現在は公開ページのみ提供中です。授業機能は準備を進めています。」
- CTA: プライマリ「サービス概要を見る」→ `/about`、セカンダリ「操作マニュアル」→ `/guide`

### 3. 実際の画面セクション（新規）

イラストや素材画像は使わず、**実装済みの教師向け画面のスクリーンショット**を使う。

- 見出し: 「教師の授業準備は、もう動いています。」
- サブ: 「授業機能全体はまだ準備中ですが、教材づくりの一部はこの画面で実際に動いています。」
- スクリーンショット1: **授業作成ウィザード**（`GuidedBuilderWizard`, `src/components/teacher/templates/GuidedBuilderWizard.tsx`）— キャプション「目標を選ぶだけで、授業の骨格ができる」
- スクリーンショット2: **教材一覧・編集画面**（`TemplateListPage` / `TemplateEditorPage`）— キャプション「作った教材は一覧でいつでも見返せる」

補足文（小さめ）: 「これらは教師アカウントでログインした状態の画面です。生徒が参加する授業本編は準備中です。」

### 4. 特徴（テキストストリップ、新規・軽量）

3カードではなく、横並びの短いテキストストリップとして配置する（画面を占有しすぎないため）。`docs/superpowers/specs/2026-08-05-integrated-platform-spec.md` の product principles を出典とする:

1. **今、必要な判断だけ** — 生徒の画面には今取るべき行動だけを表示。情報過多にしない。
2. **なぜ起きたかまで扱う** — 結果だけでなく「何が起きたか→なぜ→次にどうするか」を振り返る設計。
3. **サーバーが進行を守る** — 教師のブラウザに依存しない設計。スリープや通信断で授業が止まらない。

### 5. 対象科目セクション（新規・2カード）

`docs/superpowers/specs/2026-08-05-integrated-platform-spec.md` §12/§13 を出典とする:

- **社会科｜市場経済シミュレーション** — 需要と供給、企業と産業のつながり、景気と政策。常時売買市場で、情報をもとに投資判断を積み重ねます。
- **家庭科｜生活設計シミュレーション** — 学生から退職後まで、人生の各段階を疑似体験。1ラウンド＝5年（設定変更可）で、家計と資産形成を考えます。役割別・段階分担など、クラスの人数構成に合わせた進行形式にも対応予定。

### 6. 授業の流れセクション（新規）

README の準備中リスト（「授業教材、授業実施、参加、教室表示、売買・結果」）と表現を揃えた6ステップを横並びで表示する:

教材をつくる → 授業を実施する → 生徒が参加する → 教室に表示する → 売買する → 結果を振り返る

各ステップは短い1行の説明を添える程度に留める（詳細は `/guide` に譲る）。

### 7. クロージング（既存を維持）

現行の `landing-closing` セクション（「準備を進めています。」／「まもなく教室に市場をひらけます。」＋CTA「サービス概要を見る」→`/about`）はそのまま維持する。

### 8. フッター（既存維持・変更なし）

## 実装メモ（後続の実装計画向け）

- スクリーンショットの取得には、開発サーバー＋Firebaseエミュレータを起動し、教師認証済み状態で `/teacher/templates/new`（ウィザード）と `/teacher/templates`（一覧）または編集画面に到達する必要がある。テスト用の教師アカウント／エミュレータのAuthバイパスを使う。
- スクリーンショット画像は `src/assets/` 配下に配置し、`hero.png`（未使用）は削除するか、置き換えるかを実装時に判断する。
- 新設セクションは MUI コンポーネント（`Box`, `Stack`, `Typography` 等）を使い、既存の `landing-*` CSS 変数・命名規則（`src/App.css`）を踏襲する。
- レスポンシブ対応は既存の `landing-nav` 等と同様、モバイルでの表示崩れがないことを確認する。

## 非機能要件

- アクセシビリティ: 既存の landing page と同様、見出し階層・`aria-label`・タップ領域（min-height 44px）を踏襲する。
- パフォーマンス: スクリーンショット画像は適切に圧縮し、レイアウトシフトを避けるため width/height を明示する。
