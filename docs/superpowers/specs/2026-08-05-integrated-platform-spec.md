## 0. この文書の使い方

本書は、既存のStock League Classroomを、社会科・家庭科の授業で利用できる教育プラットフォームへ再設計するための統合仕様である。単なるロードマップではなく、実装時に判断が分かれやすい次の事項まで定義する。

- プロダクトの対象範囲と非対象範囲
- 教材、教材版、授業実施、授業状態の関係
- 教師、生徒、学校管理者、サービス運営者の権限
- 授業作成、開始、進行、停止、再開、終了の状態遷移
- 社会科の常時売買市場の注文・約定・価格計算
- 家庭科の生活設計シミュレーション
- 結果、評価、振り返り、アンケート、分析
- AI、教材共有、マーケットプレイス
- 組織、ライセンス、課金、請求書対応のデータ構造
- 未成年者のデータ、保持、削除、監査
- 障害時の安全停止、冪等性、リプレイ
- 段階的な実装順と一括公開方針

実装担当者は、本文の順に読む必要はない。最初に「1. 仕様の優先順位」「4. 用語」「7. 共通データモデル」「12. 社会科市場」「13. 家庭科」「25. 実装順」を確認するとよい。

## 2. プロダクトの目的

### 2.1 中核目的

本サービスは、生徒が情報を読み、意思決定し、その結果を観察し、理由を振り返る授業を、教師が短時間で設計・実施・再利用できるようにする。

対象となる中心領域は次のとおり。

1. 社会科・公共・政治経済
   - 企業、産業、決算、経済指標、ニュース
   - 株式市場における情報判断
   - 需要と供給による価格形成
   - 不確実性、予想、市場の織り込み
2. 家庭科・家庭基礎・家庭総合
   - 収入、支出、貯蓄、資産形成
   - 保険、住宅、借入、公的支援
   - 人生段階と生活目標
   - 経済変動やライフイベントへの対応
3. 共通授業基盤
   - チーム、参加、情報公開、投票、判断、振り返り
   - 教師画面、生徒画面、教室表示
   - 教材作成、版管理、授業実施、結果分析
4. 学校・組織向け基盤
   - 権限、教材所有、保持、監査
   - ライセンス、利用枠、将来の請求書運用
   - マーケットプレイス

### 2.2 プロダクトの原則

- 機能数を減らすのではなく、役割と授業目的に応じて表示を減らす。
- 生徒には「今必要な判断」だけを表示する。
- 教師には「次にすること」を最優先で表示する。
- 管理者には「対応が必要なこと」を最優先で表示する。
- 専門用語ではなく、利用者が実行する行動を画面文言に使う。
- 結果だけでなく、「なぜ起きたか」と「次にどうするか」を扱う。
- 正解が一つに決まらない授業では、総合点より観点別結果を重視する。
- 授業中の価格、残高、評価などの正本はサーバー側に置く。
- 将来情報や非公開係数を生徒端末へ配信しない。
- 重要操作、注文、課金、権限変更は冪等にする。
- AIが使えない環境でも、主要な授業作成・実施機能は動作する。

### 2.3 非対象・初期段階で行わないこと

- 実際の金融商品の購入推奨
- 実際の証券取引を完全再現する板取引
- 空売り、信用取引、レバレッジ
- 初期段階での成行・指値・注文優先順位を含む本格的取引所
- 現実の税制や社会保障を完全に再現する計算
- サービス内での長文レポート作成・提出管理
- 初期段階でのGoogle Classroom自動投稿・採点同期
- 政策決定、自治体予算配分、民主的合意形成の専用社会科モード
- 旧データ・旧APIの互換維持

## 3. 現行システムの基準点と廃止対象

元ロードマップで確認された現行システムの特徴は次のとおり。

- 教師判定は、匿名ではなく、メール確認済みで、Googleログインであることを中心に行っている。
- 所有権は `ownerUid` を中心とするフラットな個人所有。
- 組織、テナント、学校単位の権限がない。
- 定員80人がルールへハードコードされている。
- 価格更新は教師ブラウザが担当している。
- Cloud Functionsによるサーバー権威の約定処理がない。
- ニュース影響は全銘柄へ一律適用される。
- 生徒の売買量は価格へ影響しない。
- 生徒が読めるデータに将来価格と乱数シードが含まれる先読み脆弱性がある。

新設計では、上記を前提に互換機能を増築しない。原則として次のように置き換える。

| 旧方式 | 新方式 |
| --- | --- |
| `ownerUid`中心 | 全リソースを`orgId`所有 |
| 教師ブラウザが価格の権威 | サーバーが価格・約定の権威 |
| 毎秒クライアント更新 | 3秒を標準とする短時間バッチ処理 |
| 全銘柄一律のニュース影響 | 企業特性・業界・情報ごとの影響 |
| 売買量が価格に影響しない | 需給影響を次価格へ反映 |
| 将来情報を公開データに含む | 公開・非公開データを型とパスで分離 |
| 固定定員 | サービス、契約、授業ごとの設定に分離 |
| 旧市場との互換 | 廃止 |

## 4. 用語

内部実装では次の用語を正本とする。UIでは必要に応じて平易な名称へ置き換える。

### 4.1 教材と授業

| 日本語 | 推奨内部名 | 定義 |
| --- | --- | --- |
| 教材 | `LessonTemplate` | 教師が編集する授業内容のまとまり。下書きを持つ |
| 教材版 | `LessonVersion` | 明示的に保存された変更不可の版 |
| 授業実施 | `LessonRun` | 特定の日時・クラスで実施する1回分 |
| 授業フェーズ | `LessonPhase` | 情報確認、市場、判断、結果、振り返りなど |
| 実施状態 | `SimulationState` | 株価、保有株、家計、イベントなどの現在状態 |
| 授業意図 | `LessonIntent` | 科目、目標、時間、難易度などの作成入力 |
| 授業パッケージ | `LessonPackage` | 目的別に用意された推奨設定一式 |
| 教室表示 | `ClassroomDisplay` | プロジェクターやテレビに出す専用表示 |

### 4.2 組織と権限

| 用語 | 定義 |
| --- | --- |
| 個人組織 | 個人利用者に自動生成される1人組織 |
| 学校組織 | 学校単位の組織 |
| 上位組織 | 自治体、学校法人、教育委員会等が複数校を束ねる組織 |
| サービス運営者 | 全体管理を行う`operator` |
| 組織所有 | 教材・授業・結果等の所有主体が`orgId`であること |
| 派生 | 元教材との関係を残して別組織へ複製・改変すること |

### 4.3 市場

| 用語 | 定義 |
| --- | --- |
| 処理区間 | 注文をまとめて処理する短時間の区間。標準3秒 |
| 参考価格 | 注文時に画面へ表示されていた価格。約定保証なし |
| 約定価格 | 処理区間に適用される実際の取引価格 |
| 需給影響 | 買いと売りの偏りによる次価格への影響 |
| 価格ガード | 株価が設定値未満へ下がらないための最低価格 |
| 市場ノイズ | 情報・需給以外の小さなランダム変動 |
| 予想チェックポイント | 評価用に上昇・横ばい・下落等を記録する時点 |

## 5. 利用者と画面

### 5.1 利用者

- 生徒
- 教師
- 補助教師
- 学校組織の`owner`
- 学校組織の`admin`
- 教材担当、事務担当等の責任範囲付き管理者
- 上位組織の管理者
- サービス運営者`operator`

### 5.2 生徒画面

生徒画面は次だけを中心に表示する。

- 現在の課題・フェーズ
- 判断に必要な公開情報
- 自分またはチームの状態
- 売買、選択、投票、提案
- 残り時間、確定状況
- 短いヘルプ
- 結果と振り返り

授業で使わない機能はグレーアウトせず、原則として表示しない。

### 5.3 教師画面

教師画面の最上部には常に次を表示する。

- 次にすること
- 現在のフェーズ
- 参加・接続・提出状況
- 未対応の問題
- 教室表示で現在見えている内容

高度な設定は授業中の主要画面へ混在させない。

### 5.4 教室表示

教師画面のミラーではなく、専用URL・専用ウィンドウとする。教室表示へ送れる情報は、安全な表示部品に限定する。

教室表示には3モードを持たせる。

1. 開始スライド
   - 授業タイトル
   - 学習目標
   - 今日の流れ
   - ルール
   - 操作説明
   - QRコード、参加コード
   - 企業や人物の紹介
2. 授業中表示
   - 現在フェーズ
   - 残り時間
   - 公開ニュース
   - 株価、経済指標、匿名集計
   - 教師からの案内
3. 終了スライド
   - 最終結果
   - 観点別ランキング
   - 主な出来事
   - 判断と結果の関係
   - 振り返りの問い
   - 次回・外部課題の案内

教師は説明スライドへ一時的に切り替え、元の市場・授業画面へ戻せる。

教室表示へ送信してはならない情報:

- 本名を含む個人情報。ただし教師が明示的に許可した場合を除く
- 未提出者一覧
- 個人回答
- 将来公開予定のニュース
- 正解、内部係数、乱数シード
- 教師用の裏設定
- 個人別評価

## 6. 組織所有と権限

### 6.1 組織所有

全リソースは`orgId`を持つ。個人利用者にも個人組織を自動生成する。

```text
organizations/personal_{uid}
```

個人組織の生成はクライアントから行わず、冪等なサーバー処理で行う。

全対象リソースには、原則として次を持たせる。

```ts
interface OwnedResource {
  orgId: string
  createdByUid: string
  createdAt: Timestamp
  updatedAt: Timestamp
}
```

`orgId`と`createdByUid`は通常更新で変更不可とする。組織間移動は専用サーバー処理のみ許可する。

### 6.2 教材を組織間で扱う操作

| 操作 | 結果 |
| --- | --- |
| 複製 | 元を残し、複製先組織が新しい所有者になる |
| 移動 | 元組織から消え、移動先組織が所有者になる |
| 共有 | 所有権を変えず、利用権だけ付与する |
| 派生 | 派生先組織が所有し、元教材・元版との関係を記録する |

学校組織所有へ移した教材は、作成教師の異動・退職後も学校に残る。

### 6.3 権限の3層

1. カスタムクレーム
   - `operator`等のサービス全体権限だけを保持
2. Firestore
   - 組織メンバーシップの正本
3. RTDB
   - 授業中の高速権限判定用ミラー
4. Cloud Functions等のサーバー処理
   - 利用枠、約定、公開、課金、重要操作の最終判定

```text
organizations/{orgId}/members/{uid}
orgAccess/{orgId}/{uid}
```

RTDBミラーはAdmin SDKだけが更新し、`membershipVersion`を持つ。同期不整合時はアクセス拒否側へ倒す。

### 6.4 組織ロール

基本ロール:

- `owner`
- `admin`
- `teacher`

これに責任範囲を追加できる。

- メンバー管理
- 教材管理
- 生徒データ管理
- 契約・請求管理
- 監査ログ閲覧
- AI利用管理
- 学校設定管理

画面ではロール名だけでなく、人物ごとに「何ができるか」を表示する。

### 6.5 授業中の教師ロール

- 主担当
  - 開始、終了、市場停止、設定変更、主担当移譲
- 補助担当
  - ニュース公開、時間延長、生徒支援、接続対応
- 閲覧担当
  - 進行状況と結果の閲覧

授業のホストは端末に固定しない。主担当端末が落ちても、別教師へ権限を引き継げる。

### 6.6 権限失効

メンバー停止時は次の順で処理する。

1. Firestoreメンバーシップを`suspended`
2. RTDBミラーを`suspended`
3. `revokedAtSeconds`更新
4. Refresh Token失効
5. 非同期処理完了後に削除可能

`auth_time`と`revokedAtSeconds`は秒で統一する。

## 7. 共通データモデル

### 7.1 `LessonIntent`

```ts
interface LessonIntent {
  subject: 'SOCIAL_STUDIES' | 'HOME_ECONOMICS'
  primaryObjective: string
  secondaryObjectives: string[]
  durationMinutes: number
  studentCount: number
  deviceMode: 'ONE_PER_STUDENT' | 'ONE_PER_TEAM' | 'MIXED'
  activityMode: 'INDIVIDUAL' | 'TEAM' | 'HYBRID'
  researchDepth: 'NEWS_ONLY' | 'COMPANY_INFO' | 'FINANCIALS'
  difficulty: 'INTRODUCTORY' | 'STANDARD' | 'ADVANCED'
  theme?: string
  accessibilityNeeds?: string[]
}
```

### 7.2 `LessonTemplate`

```ts
interface LessonTemplate {
  id: string
  orgId: string
  createdByUid: string
  draft: LessonContent
  currentPublishedVersionId?: string
  status: 'DRAFT' | 'READY' | 'ARCHIVED'
  visibility: 'PRIVATE' | 'LINK' | 'ORGANIZATION' | 'PUBLIC'
  lineage?: TemplateLineage
  createdAt: Timestamp
  updatedAt: Timestamp
}
```

### 7.3 `LessonVersion`

```ts
interface LessonVersion {
  id: string
  templateId: string
  orgId: string
  schemaVersion: number
  content: LessonContent
  createdByUid: string
  createdAt: Timestamp
  changeSummary?: string
  parentVersionId?: string
  sourceTemplateId?: string
  sourceVersionId?: string
  immutable: true
}
```

教材版は作成後に変更不可。修正は新しい版を作る。

### 7.4 `LessonRun`

```ts
interface LessonRun {
  id: string
  orgId: string
  templateId: string
  templateVersionId: string
  templateSnapshot: LessonContent
  subject: 'SOCIAL_STUDIES' | 'HOME_ECONOMICS'
  status:
    | 'DRAFT'
    | 'READY'
    | 'WAITING'
    | 'RUNNING'
    | 'PAUSED'
    | 'INTERRUPTED'
    | 'REFLECTION'
    | 'COMPLETED'
    | 'ABORTED'
    | 'ARCHIVED'
  primaryTeacherUid: string
  teacherRoles: Record<string, 'PRIMARY' | 'ASSISTANT' | 'VIEWER'>
  expectedParticipants?: number
  maxParticipants?: number
  currentPhaseId?: string
  randomSeed: string
  startedAt?: Timestamp
  endedAt?: Timestamp
  createdAt: Timestamp
}
```

授業開始時に教材版とスナップショットを固定する。元教材の編集は実施中・過去の授業に影響しない。

### 7.5 `LessonPhase`

```ts
interface LessonPhase {
  id: string
  type:
    | 'INTRO'
    | 'INFORMATION'
    | 'PREDICTION'
    | 'DISCUSSION'
    | 'MARKET'
    | 'DECISION'
    | 'RESULT'
    | 'REFLECTION'
    | 'CUSTOM'
  progression:
    | 'TIMED'
    | 'SUBMISSION_BASED'
    | 'TEACHER_CONTROLLED'
    | 'AUTOMATIC'
  durationSeconds?: number
  requiredCompletionRatio?: number
  displayConfig: unknown
  inputConfig?: unknown
}
```

### 7.6 イベントログ

重要な状態変更は追記専用イベントとして保存する。

```ts
interface LessonEvent {
  eventId: string
  lessonRunId: string
  orgId: string
  type: string
  actorType: 'SYSTEM' | 'TEACHER' | 'STUDENT' | 'OPERATOR'
  actorId?: string
  idempotencyKey?: string
  payload: unknown
  serverOccurredAt: Timestamp
  sequence: number
}
```

対象:

- 参加、離脱、復帰
- ニュース公開
- 注文送信、取消、約定、不成立
- 価格更新
- 回答、投票、確定
- フェーズ変更
- 教師介入
- チェックポイント
- 一時停止、再開、終了
- 補正
- エラー、安全停止

### 7.7 チェックポイントとリプレイ

```ts
interface LessonCheckpoint {
  id: string
  lessonRunId: string
  sequence: number
  phaseId: string
  snapshot: SimulationState
  createdBy: 'SYSTEM' | 'TEACHER'
  createdAt: Timestamp
}
```

- 自動チェックポイントを主要フェーズ境界で作成する。
- 教師は任意の位置を再開地点として保存できる。
- リプレイはイベント列と乱数シードを使う。
- リプレイは閲覧専用で元結果を変更しない。
- 障害調査、教材審査、教師の授業振り返りに利用する。

## 8. 授業のライフサイクル

### 8.1 教材作成

```text
下書き編集
→ 自動保存
→ 自動チェック
→ 生徒として試す
→ 高速シミュレーション
→ 教材版を保存
→ 授業実施を作成
```

### 8.2 授業実施の状態

1. `DRAFT`
   - 教師のみ
   - 生徒参加不可
2. `READY`
   - 参加コード発行可能
   - 重要変更時に影響を警告
3. `WAITING`
   - 生徒は待機画面へ参加
   - チーム・接続確認
4. `RUNNING`
   - 実施版を固定
5. `PAUSED`
   - 新規操作停止
   - 状態保存
6. `INTERRUPTED`
   - 障害・時間不足等で次回再開
7. `REFLECTION`
   - 売買・主要判断を停止
   - アンケート・結果確認
8. `COMPLETED`
   - 結果確定
9. `ABORTED`
   - 現在地点で打ち切り
10. `ARCHIVED`
   - 年度アーカイブ等

### 8.3 開始前テスト

#### 自動チェック

- 必須設定不足
- 金額・株数・条件の矛盾
- 公開されない情報
- 終了条件がないフェーズ
- 進行不能な分岐
- 想定時間超過
- 生徒に必要情報が届かない
- 終了画面が生成できない
- 計算結果が非数、負値、異常値になる

結果:

- 公開可能
- 注意事項あり
- 修正が必要

重大な進行不能や安全問題だけ公開を阻止する。時間超過や偏った結果は警告に留める。

#### 生徒として試す

- 仮生徒・仮チームで操作
- 教室表示を確認
- テストデータは本番から分離

#### 高速シミュレーション

- 仮想チームを自動で動かす
- 全フェーズを通過
- 株価・家計の極端な結果を検出
- 結果画面、ランキング、アンケートを生成

### 8.4 待機画面

生徒:

- 参加完了
- 自分のチーム
- 表示名
- 授業タイトル
- 開始までの案内
- 30秒程度の操作練習

教師:

- 参加済み、未参加、重複
- 接続状態
- チーム人数の偏り
- 開始前の対応事項

教室表示:

- タイトル
- QRコード
- 参加コード
- 参加人数
- 開始スライド

### 8.5 終了方法

#### 通常終了

- 新しい操作停止
- 処理中注文を確定
- 最終結果計算
- 終了スライド
- アンケート開始

#### 途中終了・次回再開

- 現在状態保存
- 暫定結果
- 再開地点指定
- 生徒へ続きがある旨を表示

#### 現在地点で打ち切り

- ここまでを確定
- 未実施部分を評価対象外
- 理由を記録
- 短縮終了画面

終了前に、未確定注文、未提出、未公開情報を教師へ表示する。

## 12. 社会科・市場経済シミュレーション

### 12.1 実装範囲

初期実装:

- 市場・経済シミュレーション

テーマとして利用可能:

- 政策
- 地域
- 防災
- 観光
- 環境
- 国際経済

将来拡張:

- 政策決定
- 自治体予算配分
- 民主的合意形成
- 複数の社会的役割を操作するモード

初期段階の生徒役割は、投資家に統一する。企業、政府、消費者等は、情報・イベント・影響要因として登場するが、生徒が毎ラウンド操作する役にはしない。

### 12.2 公式学習パッケージ

1. 需要と供給による価格形成
2. 情報を基にした意思決定
3. 企業・産業のつながり
4. 景気・政策と市場
5. 情報の不確実性とメディアリテラシー
6. 総合経済シミュレーション

### 12.3 進行形式

#### 共通市場型

- 全員が同じ企業・同じ情報
- 比較しやすい
- 初回・50分授業向け

#### 担当企業型

- チームごとに異なる企業・業界を重点担当
- 同じニュースの影響差を学ぶ

#### 分散投資型

- 複数企業へ自由に投資
- ポートフォリオとリスク管理
- 発展授業向け

標準は共通市場型。

### 12.4 企業・銘柄

各企業は次を持つ。

```ts
interface SimulatedCompany {
  id: string
  name: string
  symbol: string
  industry: string
  description: string
  productsAndServices: string[]
  domesticRevenueRatio?: number
  overseasRevenueRatio?: number
  costDrivers: string[]
  sizeClass: 'SMALL' | 'MEDIUM' | 'LARGE'
  financialStrength: 'WEAK' | 'STANDARD' | 'STRONG'
  growthProfile: 'STABLE' | 'GROWTH' | 'CYCLICAL'
  riskFactors: string[]
  initialPrice: number
  minimumPriceGuard: PriceGuard
  impactSensitivities: Record<string, number>
}
```

難易度別表示:

- 初級: 業界、商品、強み、弱み
- 標準: 売上構成、費用構成、海外依存、業績推移
- 発展: 利益率、負債、キャッシュフロー、競合比較

標準企業数は4〜6社。50分入門は3〜4社でもよい。初期は現実的な架空企業を標準にする。

### 12.5 情報カテゴリ

1. 公式ニュース
   - 政府発表
   - 企業発表
   - 政策変更
   - 事故・不祥事
2. 市場データ
   - 株価
   - 出来高相当の売買量
   - 為替
   - 金利
   - 物価
   - 業界指数
3. 決算・企業情報
   - 売上
   - 営業利益
   - 純利益
   - 前年同期比
   - 業績予想
   - 配当情報
   - 事業別実績
4. 解説・予測
   - 専門家コメント
   - アナリスト予測
   - 業界見通し
5. 不確かな情報
   - SNS
   - うわさ
   - 未確認情報

各情報に次を持たせる。

- 情報源
- 公開時刻
- 事実、予測、意見の区分
- 信頼度の目安: 高、中、不明
- 対象企業・業界
- 生徒公開本文
- 教師用の意図・影響設定

### 12.6 決算難易度

初級:

- 売上が増えたか
- 利益が増えたか
- 会社予想を上回ったか

標準:

- 前年同期比
- 利益率
- 業績予想修正
- 事業別成績

発展:

- キャッシュフロー
- 一時要因
- 市場予想との差
- 将来投資と短期利益

「利益増加なら必ず株価上昇」にはしない。市場の事前予想、織り込み、将来見通し、他社比較を扱える。

### 12.7 情報の不確実性

各情報は裏側で次を持つ。

```ts
interface InformationImpact {
  baseDirection: 'POSITIVE' | 'NEGATIVE' | 'MIXED' | 'NEUTRAL'
  strength: number
  marketExpectation?: number
  interactions?: string[]
  shortTermImpact?: number
  longTermImpact?: number
}
```

難易度:

- 初級: 方向が比較的明確
- 標準: 複数情報を組み合わせる
- 発展: 市場予想、織り込み、競合情報

結果画面には、主因、予想と異なった理由、別解の余地を表示する。

### 12.8 経済指標・政策

分類:

- 景気
- 物価
- 金利
- 為替
- 税、補助金、規制、公共投資等の政策

生徒表示:

- 初級: 円安、利上げ、景気悪化等の言葉
- 標準: 数値変化
- 発展: 複数指標、予想との差、短期・長期

影響は全企業一律ではなく企業特性と結び付ける。

### 12.9 常時売買の基本方式

生徒は市場が開いている間、常時注文できる。内部では短時間バッチ処理を繰り返す。

```text
注文受付
→ 3秒区間へ格納
→ 区間締切
→ 注文検証
→ 同一区間を同一価格で約定
→ 需給・情報・ノイズから次価格計算
→ 次区間
```

既定値:

- 処理間隔: 3秒
- 教師変更範囲: 1〜10秒
- 端末ではなくサーバー時刻を正本にする
- 生徒画面に次回処理までの時間を表示
- 授業途中で間隔を変えた場合は全員へ通知

### 12.10 同一区間の公平性

- 同一区間の注文は同じ約定価格。
- 通信到着順で価格差を付けない。
- 注文時刻は履歴に残すが優先順位に使わない。
- 買い・売りの合計は次価格の需給影響へ使う。

### 12.11 参考価格と約定価格

注文時の価格は参考価格であり保証しない。価格差が大きくても自動確認や注文停止を行わず、そのまま約定する。

注文前表示:

```text
注文時の参考価格: 1,200円
この価格での約定は保証されません
次回処理時の価格で約定します
```

約定後表示:

```text
5株を1,260円で購入しました
注文時の参考価格: 1,200円
価格差: +60円（+5.0%）
```

履歴には参考価格、約定価格、価格差を保存する。

### 12.12 注文モデル

```ts
interface MarketOrder {
  orderId: string
  idempotencyKey: string
  lessonRunId: string
  batchId: string
  participantId?: string
  teamId: string
  stockId: string
  side: 'BUY' | 'SELL'
  quantity: number
  referencePrice: number
  status:
    | 'PENDING'
    | 'CANCELLED'
    | 'PROCESSING'
    | 'FILLED'
    | 'REJECTED'
  submittedAtServer: Timestamp
  settledAtServer?: Timestamp
  executionPrice?: number
  rejectionReason?: string
}
```

### 12.13 冪等性と二重送信

- 全注文に一意IDと冪等キーを付ける。
- 同一キーは1回だけ処理する。
- 送信中はボタンを一時無効化する。
- 成功、失敗、処理中を明示する。
- 再接続時にサーバーへ結果を照会する。
- 教師操作、利用枠確保、課金にも同様の仕組みを使う。

### 12.14 同一区間の買い・売り相殺

同じ銘柄について同一区間に買いと売りがある場合、差し引く。

- 5株買い + 2株売り = 3株買い
- 同数 = 売買なし
- 元注文と差引後結果の両方を履歴に残す
- 手数料有効時は差引後数量へ適用

### 12.15 資金・株数不足

#### 同一区間の複数買い

- 複数銘柄を含む買い注文合計を一括判定する。
- 合計が区間開始時の利用可能現金を超えた場合、その区間の買い注文をすべて不成立。
- 一部約定はしない。
- 売却注文は保有株範囲なら別に成立。

#### 売り過ぎ

- 売却合計が保有株を超えた場合、その区間の当該売り注文をすべて不成立。
- 一部約定はしない。

#### 売却代金

- 同一区間で得る売却代金は、その区間の購入には使えない。
- 次の区間から利用可能。

### 12.16 注文中資金・株の拘束

購入注文送信時:

- 参考価格×株数を注文中資金として一時拘束
- 利用可能現金から差し引いて表示
- 約定後に差額精算
- 不成立なら解放
- 約定価格上昇で資金不足なら、区間の買い注文は不成立

売却注文送信時:

- 注文中株を売却可能数から差し引く
- 約定後に保有株へ反映
- 不成立なら戻す

表示例:

```text
現金: 20,000円
注文中: 6,000円
利用可能: 14,000円

保有: 10株
売却注文中: 4株
追加売却可能: 6株
```

### 12.17 処理待ち注文の取消

- `PENDING`中は取消可能。
- 取消時に拘束資金・株を即時解放。
- 区間締切後、`PROCESSING`へ移ったら取消不可。
- 約定済み注文は原則取消不可。

約定後の誤操作:

- 教師が補正取引または残高・保有補正を追加する。
- 元約定は削除しない。
- 重大障害のみ、市場全体をチェックポイントへ戻す。

### 12.18 売買上限

既定値は無制限。

- 1回の注文上限: 無制限
- 一定時間内の注文回数: 無制限
- 1銘柄保有上限: 設けない
- 全銘柄合計保有上限: 設けない

教師は必要な場合だけ、1回の注文上限や回数制限を設定できる。

購入可能数は現金、売却可能数は保有株だけで決まる。

### 12.19 発行株数・在庫

- 発行株数による売り切れは扱わない。
- 株は市場から無限に購入可能とみなす。
- 需給は注文の偏りから計算する。
- 本格的な板・数量一致は将来機能。

### 12.20 価格計算

概念式:

```ts
rawChangePercent =
  informationImpactPercent
  + demandImpactPercent
  + marketNoisePercent

nextPrice =
  applyPriceGuard(
    currentPrice * (1 + rawChangePercent / 100)
  )
```

最終的な感度や係数は教材設定で調整可能にする。教師には原則として次の抽象設定を見せる。

- 情報重視
- バランス
- 需給重視

価格変動の標準上限は設けない。急騰・急落しても注文を止めず、警告を表示する。教師は手動で市場を停止できる。

### 12.21 需給影響

買いと売りの金額差を使う。

```ts
netDemandValue = totalBuyValue - totalSellValue
demandRatio = netDemandValue / effectiveMarketSize
demandImpactPercent = demandRatio * sensitivity
```

`effectiveMarketSize`は、教師に発行株数を入力させず、企業規模・変動しやすさとして設定する。

- 小さい企業: 動きやすい
- 標準
- 大きい企業: 動きにくい

上限を設定する場合も、詳細設定に置き、既定では極端に抑え過ぎない。

### 12.22 市場ノイズ

- 標準では小さいノイズを有効。
- 初級は無効にできる。
- 3秒区間ごとに適用。
- 乱数シードを保存。
- 生徒には「その他要因」と表示。
- 標準目安: ±0.2〜0.5%程度。実際の値はテストで調整。

### 12.23 価格ガード

```ts
type PriceGuard =
  | { type: 'ABSOLUTE'; minimumPrice: number }
  | { type: 'PERCENT_OF_INITIAL'; minimumPercent: number }
```

- 標準最低値は1円。
- 教師は銘柄ごとに最低10円、100円、初期価格の10%等を設定可能。
- ガード到達後も売買可能。
- 売り圧力の超過分は次回へ持ち越さない。
- 買いが増えればガードから再上昇可能。
- 生徒へ「価格ガードに到達」「売り圧力があるが最低価格で停止」と表示。
- 倒産イベントだけガードを無視し、価値を0円にできる。

### 12.24 急変表示

価格変動に標準上限を設けない代わりに、次を行う。

- 急変警告
- 教室表示への表示
- 教師画面のアラート
- 教師による一時停止
- 感度設定の事前テスト

### 12.25 市場停止

停止確定前に受理済みの注文:

- 通常どおり約定

停止後:

- 新規注文を拒否
- 注文ボタン無効
- 教師は処理待ち注文を強制取消可能

停止表示:

- 最終価格を固定表示
- 「市場停止中」
- 再開方法・時刻
- 新しいニュースを公開可能

### 12.26 市場再開

- 教師は再開前確認時間を設定可能。
- 標準30秒。
- 確認中は情報閲覧のみ。
- 全員同時に注文受付開始。
- 確認なしの即時再開も可能。

再開後最初の区間:

- 停止時点価格で同一価格約定
- 注文偏りは次価格へ反映
- 特別補正なし

### 12.27 ニュース公開直後の売買

教師設定:

- 市場を止めず公開
- 公開時に自動停止
- 公開後の確認時間
- 確認後自動再開
- 手動再開

### 12.28 配当、分割、手数料

- 配当: 標準無効、教材ごとに有効化可能
- 株式分割: 標準無効
- 取引手数料: 標準0円
- 有効時は生徒へ計算方法を事前表示
- 空売り、信用取引、レバレッジは初期非対応

### 12.29 倒産・取引停止

倒産:

- 倒産確定で新規売買停止
- 処理待ち注文は不成立
- 保有株価値を0円
- チャートへ倒産時点
- 理由と影響情報を表示
- 標準は無効

倒産前の一時停止も設定可能。

### 12.30 価格履歴とチャート

- 3秒ごとの価格を保存。
- 生徒画面は直近推移中心。
- 表示は10〜30秒単位へ集約可能。
- ニュース・決算公開時刻をチャートへ表示。
- 教師は全期間、特定期間、銘柄比較を切替。
- 授業後に全履歴とCSV。

### 12.31 価格変動理由の表示

生徒には内訳を表示するが、内部係数は見せない。

```text
ニュース要因  +4.2%
需給要因      -1.1%
その他要因    +0.2%
最終変動      +3.3%
```

教師・教材作成者は詳細設定と計算ログを確認できる。

### 12.32 予想チェックポイント

常時売買とは別に、ニュース・決算公開時等に評価用予想を記録する。

- 上昇
- 横ばい
- 下落
- 根拠情報
- 確信度を任意で追加可能

いつの予想を評価するかを明確にし、売買履歴だけから予想を推定しない。

### 12.33 社会科の評価

1. 運用結果
   - 最終資産
   - 利益率
2. 予想精度
3. 情報活用
4. リスク管理
5. 振り返り

観点別ランキングを標準にする。教師は重みを変更可能。

例:

```text
情報活用 40%
予想精度 30%
振り返り 20%
運用結果 10%
```

学校祭等では資産順位を前面に出せる。

### 12.34 授業時間別の標準構成

#### 50分

- 導入8分
- 企業確認7分
- 市場20分
- 結果5分
- 振り返り10分
- 3〜4社
- ニュース2〜3回

#### 2時間

- 企業分析
- 市場前半
- 決算・追加情報
- 市場後半
- 振り返り
- 4〜6社

#### 複数時間

- 業界分析
- 投資方針
- 複数回の市場
- 結果分析
- 発表・相互評価
- 不確実性と経済指標

#### イベント

- 説明短縮
- 大人数向け簡略表示
- チーム端末中心
- 資産順位を前面
- 詳細振り返り任意
- 処理負荷に応じて更新頻度・表示詳細を抑制可能

授業遅延時のワンタップ短縮:

- ニュース省略
- 市場時間短縮
- アンケートを後回し

## 13. 家庭科・生活設計シミュレーション

### 13.1 基本単位

標準:

- 1ラウンド = 5年
- 6ラウンド程度で人生を扱う

任意:

- 1ラウンド = 1年

### 13.2 人生段階

- 学生
- 自立
- 家族形成
- 子育て
- 子育て後・老後準備
- 退職後

全員が必ず同じ順で進む必要はない。教材により開始地点・経路を変えられる。

難易度:

- 導入: 1段階
- 標準: 1〜3段階
- 発展: 生涯全体

### 13.3 授業形式

#### 共通条件

- 全チーム同じプロフィール、初期資産、収入、イベント
- 判断差を比較
- 標準

#### 役割・人物別

- チームやクラス内で異なるプロフィール
- 条件差を比較
- 発展

#### クラス段階分担

- チームごとに異なる人生段階を担当
- 最後にクラスで共有

#### チーム内複数人物

- 同一チームで複数プロフィールを比較

### 13.4 コアプロフィール

最低限の7項目:

1. 年齢
2. 世帯収入
3. 年間生活費
4. 現金・貯蓄
5. 家族
6. 住居
7. 人生目標

実在する生徒本人の情報ではなく、架空プロフィールを標準にする。

生徒画面上部に常時表示:

```text
担当人物: ケースB
32歳・子育て期
目標: 住宅購入と教育資金
これは授業用の架空プロフィールです
```

### 13.5 資産

標準の簡略セット:

- 現金
- 普通・定期預金
- 債券
- 国内株式
- 海外株式
- 投資信託

教材目的に不要な資産は表示しない。

### 13.6 保険

保険は資産と分離する。

```ts
interface HouseholdState {
  assets: AssetPosition[]
  insuranceContracts: InsuranceContract[]
  cashFlows: CashFlow[]
  liabilities: Liability[]
}
```

保険:

- 保険料
- 対象リスク
- 給付条件
- 給付額
- 契約期間

資産配分円グラフへ保険を混ぜない。

### 13.7 収入・支出

- 年単位で集計
- 給与、事業収入、給付等
- 住居費、食費、教育費、交通、保険料等
- 固定費と変動費を区別可能
- 人生段階で変動

### 13.8 税・社会保険

- 教育用の簡略式
- 実際の税率へ依存し過ぎない
- 教材内に説明を持つ
- 数値・式の版を教材版へ固定
- 制度名を使う場合は基準年を明記

### 13.9 住宅・ローン

- 賃貸
- 住宅購入
- 頭金
- 借入
- 金利
- 返済期間
- 元利均等返済を基本
- 繰上返済等は発展

### 13.10 公的支援

- 条件を満たした場合に選択可能
- 条件・効果を簡略表示
- 自動適用か申請選択かを教材で設定
- 制度の完全再現を目的にしない

### 13.11 経済要因

- 物価
- 金利
- 為替
- 景気
- 資産収益率

物価は生活費、金利は預金・借入、景気は収入・失業等へ反映する。

### 13.12 イベント

公開方法:

- 事前予告
- 一部予告
- 非公開

例:

- 進学
- 就職
- 結婚
- 出産
- 住宅購入
- 病気
- 失業
- 災害
- 物価上昇
- 金利上昇

授業ごとに、共通イベントまたは人物別イベントを選べる。

### 13.13 資金不足

資金不足時に選択肢を提示する。

- 支出削減
- 資産売却
- 借入
- 公的支援
- 目標延期
- 教材で許可されたその他対応

自動で破綻させず、判断機会として扱う。

### 13.14 退職後

- 収入減少
- 年金等の簡略給付
- 資産取り崩し
- 医療・介護イベント
- 生活費
- 長寿リスク

### 13.15 家庭科の計算

最初は教育用の簡略モデル。

- 収入・支出: 年単位
- 税・社会保険: 簡略式
- 住宅ローン: 元利均等
- 保険: 保険料と給付条件を簡略化
- 資産: 年次収益率
- 物価: 生活費へ反映
- 失業・病気: イベント
- 公的支援: 条件適合時に選択
- 資金不足: 借入、支出削減、資産売却等

教師には計算式より影響の強さを見せる。

- 影響なし
- 小さい
- 標準
- 大きい
- 数値を直接指定

高度な作成者だけ詳細式を編集できる。

### 13.16 目標パッケージ

目的に関係しない概念を隠す。

例:

- 緊急予備資金
- 住宅購入
- 教育資金
- 老後準備
- リスク分散
- 保険と備え
- 生活全体のバランス

### 13.17 評価

資産額だけにしない。

- 生活目標達成
- 緊急予備資金
- 生活安定性
- 分散
- 最大下落耐性
- 借入負担
- 保険の適合
- 意思決定理由
- 振り返り

総合点より観点別表示を優先する。

### 13.18 保存・再開

- 複数授業にまたがる保存
- 人生段階の途中再開
- チーム・人物単位の状態
- 欠席者補完
- 教師チェックポイント
- 版と乱数シード固定

## 17. マーケットプレイス

### 17.1 公開範囲

- 非公開
- リンク限定
- 組織内
- コミュニティ公開
- 認証済み
- 公式

### 17.2 公開資格

- メール確認済み教師はコミュニティ公開可能。
- 自動検査を行う。
- 致命的な技術・安全・権利問題は公開阻止。
- その他警告は教師が確認して公開可能。

### 17.3 派生許諾

一般公開は派生利用許諾を含む。

- 外部派生禁止の学校は一般公開不可。
- 公開停止後も取得済み派生教材は原則残る。
- 著作権、個人情報等の重大問題は例外。
- 一般公開権限を学校側で制限可能。
- すべての公開教材の派生元・版を記録。

単なるコピーも内部的には派生として記録する。

### 17.4 料金

初期マーケットプレイス教材はすべて無料。

### 17.5 レビュー

- 実際に授業で使用した教師だけレビュー可能。
- 観点別評価。
- コメント・Q&Aはレビューと分離。
- 認証は版単位。
- 公式教材も版管理。

### 17.6 削除

通常:

- 公開停止
- 派生教材は残る

重大な権利・個人情報問題:

- 原本・派生への対応を運営者が判断
- 非公開化、削除、通知
- 審査・対応ログ

### 17.7 審査

自動・人手で次を確認。

- 個人情報
- 著作権・出典
- 実在企業の虚偽
- 投資推奨と誤解される表現
- 差別・不適切内容
- 学習目標
- 政策・政治の複数視点
- AI確認状況
- 技術的完走
- 所要時間

## 19. 上位組織と学校

### 19.1 階層

```text
自治体・学校法人
  ├─ 学校A
  ├─ 学校B
  └─ 学校C
```

### 19.2 上位組織の権限

- 契約
- 利用枠配分
- 学校追加・削除
- 匿名集計
- 上位ポリシー
- 学校管理者支援

上位組織は学校の生徒個票を標準では見ない。生徒データの管理主体は学校。

### 19.3 枠配分

- 共有プール
- 学校ごとの最低保証
- 追加配分
- 利用状況

### 19.4 契約終了

- 上位契約終了後も学校データを保持。
- 学校単独契約へ移行可能。
- 即時削除しない。
- 学校追加・削除もデータ所有を壊さない。

### 20.2 初期設定ウィザード

最初に決めるのは5項目程度。

- 管理者と責任範囲
- 教材共有
- 生徒データ保持
- AI・アップロード
- 教師席・利用枠

目的別プリセット:

- 交流重視
- 情報管理重視

### 20.3 設定継承

1. サービス既定

- 必須: 学校が変更不可

UIに、学校独自、継承、ロックを表示。

### 20.4 設定反映

即時反映候補:

- 新規教材公開停止
- AI新規利用停止
- 新規アップロード停止
- メンバーアクセス停止

次回から反映候補:

- テンプレート既定
- 保持期間
- 評価既定
- 新規授業上限

進行中授業は開始時設定を原則維持。安全・個人情報上の緊急時だけ即時停止可能。

### 20.5 重要操作

- 通常: 確認なしまたは簡単な確認
- 重要: 影響範囲表示
- 重大: 再認証、理由、確認文字

重大例:

- 組織削除
- 生徒データ一括削除
- owner変更
- 大量メンバー削除
- 契約即時停止

### 20.6 下書き・予約実行

予約可能:

- 年度アーカイブ
- ロール・教師席の年度切替
- 保持期限処理
- プラン縮小
- 次年度設定

緊急停止は即時。

### 20.7 変更取消

一定期間取り消せる:

- ロール
- 教師席
- 公開範囲
- 組織設定
- 年度アーカイブ
- メンバー休止

取り消せない:

- 完全削除
- 匿名化
- 決済
- 監査ログ出力
- 正式な個人データ削除

目安:

- 設定変更7日
- メンバー休止30日
- 年度アーカイブは処理完了まで

## 21. 生徒データ、保持、削除、監査

### 21.1 個人単位機能

個人単位の削除・エクスポート・匿名化は、有料・エンタープライズ限定にせず基盤機能として提供する。

### 21.2 保持期限

組織は保持期間を選べる。

期限到来時:

- 自動削除しない。
- 対応待ちにする。
- 管理者が匿名化、削除、延長を選ぶ。

延長:

- 理由
- 新しい期限
- 無期限延長不可
- 年1回再承認

承認:

- 単独または二者承認
- 標準は単独

### 21.3 削除の優先順位

1. 本人・学校からの正式な完全削除要求
   - 復元期間なし
2. 通常保持期限
   - 管理者確認後
3. 教師の誤操作
   - 30日復元

### 21.4 ソフト削除

通常削除は30日間復元可能。ただし、法的・プライバシー上の完全削除は対象外。

### 21.5 管理者の個人データ閲覧

- 匿名集計が標準。
- 個票は理由入力。
- 時間制限。
- 監査ログ。
- `owner`は広範、`admin`は責任範囲、教師は自分の授業。

### 21.6 監査ログ

記録:

- 誰が
- いつ
- 何を
- どの組織・授業へ
- 変更前後
- 理由
- 結果

監査ログは改変不可。個人情報を不要に複製しない。

### 21.7 エクスポート

- 個人
- 授業
- 組織一括
- CSV・JSON等
- 大規模出力はownerを標準権限

## 23. 安全性、障害対応、通知、アクセシビリティ

### 23.1 安全停止

異常検知:

```text
新規操作停止
→ 状態保存
→ 処理中操作の確定
→ 教師へ原因・影響
→ 復旧方法
```

教師選択:

- 同状態から再開
- チェックポイントへ戻す
- 問題機能だけ無効
- 現在結果で終了
- 教室表示と口頭授業へ切替

生徒表示:

```text
授業を一時停止しています
先生の案内を待ってください
```

### 23.2 教師介入

通常:

- 時間延長
- 代理確定
- 担当変更
- 再接続
- スライド切替

訂正:

- 未約定注文取消
- ニュース訂正
- 状態補正
- 直前フェーズ復帰

緊急:

- 全体停止
- 情報非表示
- 参加者操作停止
- チェックポイント復元

すべて理由・変更前後を記録。

### 23.3 通知

重要:

- 開始・終了
- 締切
- 緊急停止
- 担当交代
- 教師指示

通常:

- ニュース
- 決算
- 提案
- 確定
- 残り時間

参考:

- 株価更新
- 閲覧状況
- 軽微な変更

標準は重要通知だけ音。履歴を残す。

### 23.4 ヘルプ

- 初回30秒案内
- ボタン横の短い説明
- 注文できない理由
- 次へ進めない理由
- 通信切断時の案内
- 教師へ困りごとの集計

### 23.5 アクセシビリティ

- スマホ、タブレット、PC
- 文字拡大
- 色だけで表現しない
- 十分大きな操作領域
- キーボード
- 読み上げラベル
- アニメーション低減
- 高コントラスト
- 個別時間延長
- 教師代理操作
- 自由記述を選択式へ変更可能

### 23.6 表示名

- 教師画面: 本名を原則表示
- 生徒画面: 自分・チームメンバー
- 他チーム: チーム名
- 教室表示標準: チーム名

## 26. 実装上の不変条件

実装担当AIは、次を破ってはならない。

1. 生徒へ将来価格、非公開影響係数、乱数シードを送らない。
2. 約定済み注文を削除して履歴を書き換えない。
3. 価格・残高・保有株の正本をクライアントへ置かない。
4. 同一冪等キーを複数回実行しない。
5. 授業開始後に元教材の変更を反映しない。
6. 教室表示で教師画面を直接ミラーしない。
7. AIへ個人情報を標準送信しない。
8. 一般公開教材を派生禁止として扱わない。
9. 正式な完全削除要求をソフト削除へ回さない。
10. 旧データ互換のために新モデルを複雑化しない。
11. 教師のブラウザ停止で市場処理が止まる設計にしない。
12. 同一区間の通信到着順で価格差を付けない。
13. 同一区間の売却代金を同一区間の購入へ使わない。
14. 資金不足時に黙って一部約定しない。
15. 家庭科で保険を資産と同列に扱わない。
16. 生徒の実生活情報入力を標準にしない。
17. 重要設定変更・権限変更・課金処理をクライアントだけで確定しない。
18. 組織アクセスミラーの不整合時に許可側へ倒さない。

## 27. 受け入れテスト

### 27.1 セキュリティ

- 生徒が非公開価格情報を読めない。
- 別組織の教材・結果を読めない。
- 停止済みメンバーが授業へアクセスできない。
- 教室表示から個人データを取得できない。
- クライアントが`orgId`を書き換えられない。
- AI送信前に禁止データが除外される。

### 27.2 市場

- 同一区間の全注文が同価格。
- 二重送信が1回だけ約定。
- 処理中取消不可。
- 資金不足の買い注文が全不成立。
- 同一区間売却代金が購入に使われない。
- 参考価格と約定価格が履歴に残る。
- 価格ガードを下回らない。
- 倒産時だけ0円になる。
- 停止後注文が受理されない。
- 再開確認時間後に同時受付。
- リプレイで同じイベント列を再現できる。

### 27.3 授業

- 教材版固定後、元教材編集が影響しない。
- 教師端末切断後も別教師が引継可能。
- 生徒が別端末で復帰可能。
- 欠席・途中参加が状態を壊さない。
- 途中終了から再開可能。
- 教室表示に禁止情報が出ない。
- アンケートと結果が紐付く。

### 27.4 家庭科

- 資産、保険、負債、キャッシュフローが分離。
- 物価・金利が指定項目へ反映。
- 資金不足時に選択肢が出る。
- 同一条件モードで全チームの初期条件が一致。
- 人生段階をまたいで保存・再開。
- 価格・税率等の教材版が固定。

### 27.5 組織・課金

- 利用枠仮確保が失敗時に返却。
- ダウングレードが進行中授業を止めない。
- 請求書・振込・手動状態を保存可能。
- 上位組織が生徒個票を標準閲覧できない。
- 学校が上位契約から外れてもデータを失わない。

## 30. 実装担当AIへの指示

1. いきなり全機能をコーディングせず、データモデル、状態遷移、セキュリティルール、イベント処理境界を先に提示する。
2. 旧コードを利用する場合も、旧仕様の互換を目的にしない。
3. FirestoreとRTDBを跨ぐ処理は、部分失敗、再試行、冪等性を設計する。
4. 注文・約定・価格更新は、単体テストだけでなく並行実行テストを作る。
5. セキュリティルールはEmulatorで生徒、教師、管理者、別組織、停止済みメンバーを検証する。
6. 生徒へ配信するDTOと、教師・サーバー内部DTOを別型にする。
7. 教室表示は専用の読み取りモデルを使う。
8. UIは、管理者・教師・生徒の複雑性低減原則に従う。
9. 詳細設定は利用可能にしつつ、標準フローから隠す。
10. 数値既定値は設定可能にし、コードへ散在させない。
11. すべての重要決定について、理由、変更前後、影響範囲をログへ残す。
12. 未確定の法的判断を、技術仕様だけで確定事項として扱わない。
13. 機能完了条件を受け入れテストへ落とし込み、UI完成だけで完了としない。
14. 実装中に本書内の矛盾を発見した場合、黙って補完せず、該当箇所、選択肢、推奨案を提示する。
