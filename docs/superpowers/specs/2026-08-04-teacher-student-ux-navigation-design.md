# 教師・生徒UX/ナビゲーション再設計

## 背景・課題

現在のUIは、教師・生徒ともに「次に何をすればいいか」「このボタンが何をするか」が分かりづらい。コード監査とUX原則に基づき、以下の具体的な問題を特定した。

### 教師側

- サイドバー（`TeacherShell`）に「シナリオ・ニュース予約」「MCコントロール」「ID発行・ステータス」「参加承認・参加者」という4つの異なるラベル・アイコンの項目があるが、すべて同じ `/teacher/markets/:id/host` に遷移する。実態と乖離した情報アーキテクチャが、教師に「別々の機能がある」という誤解を与える。
- 参加者承認パネル（`AdmissionPanel`）が「市場の管理」画面（`MarketDashboard`）と「HostConsole」画面の両方に同一内容で存在し、どちらで操作すべきか不明瞭。
- `HostStatusPanel` に「緊急暴落」「緊急急騰」ボタン、各行に「詳細」リンクがあるが、クリックしても何も起きない未実装の飾りである。
- サイドバーの「情報照会端末」が常時disabledで表示され、説明もない死んだメニュー項目になっている。
- 市場のライフサイクル（準備中→取引中→結果を確定中→終了）を可視化する導線が、初回のみ表示されるモーダル（`OnboardingWizard`）に依存しており、Host Console画面自体には進捗表示がない。

### 生徒側

- 参加承認後、説明なしにいきなり売買画面（`TradePanel`）に入る。「チームで資金・株を共有している」という重要な前提が結果画面（`ResultsView`）まで明示されない。
- 「復帰コード」が参加直後から目立つ位置（ポートフォリオカード）に常時表示されるが、使う場面（別端末での復帰時）まで意味が分からない。
- ステータス表示が `OPEN`/`CONNECTING` など英語のシステム用語のまま生徒に見えており、教師側の日本語ラベルと表記が揃っていない。

## スコープ・前提

- 教師・生徒どちらの体験も同じ比重で改善する。
- 情報アーキテクチャ（画面構成・遷移構造）は、既存のFirebaseリアルタイム同期アーキテクチャ（ホストリース、RTDBリスナー等）を壊さない範囲で、画面統合・再構成を行ってよい。
- 主要URLの互換性は必須要件ではない。変更する場合はリダイレクトで対応する。
- UIライブラリはMUIを引き続き使用する。
- 具体的なユーザーからの苦情ではなく、コード監査と一般的なUX原則に基づく設計とする。

## 設計

### 1. 全体の情報アーキテクチャ

#### 教師側サイトマップ（見直し後）

```
/teacher/markets           市場の準備（テンプレート選択・市場作成・市場一覧・結果CSV取得）
/teacher/markets/:id/room  市場のコントロールルーム（旧 .../host を統合・改称）
  ├─ タブ: 参加受付          (AdmissionPanel)
  ├─ タブ: 進行操作          (ホスト取得・開始/終了・価格テーブル)
  ├─ タブ: ニュース配信       (Manual News)
  └─ タブ: 教室画面           (Signageを開く導線。別タブで開く別画面のまま)
/templates                 テンプレート編集（現状維持）
```

サイドバー構成:

```
市場を準備する
  └ 市場の管理 (/teacher/markets)
  └ テンプレート (/templates)
この市場を進行する   ← marketId選択時のみ活性化
  └ コントロールルーム (/teacher/markets/:id/room)
  └ 教室画面 (/markets/:id/signage)
サポート
  └ 使い方を見る
```

「シナリオ・ニュース予約」「MCコントロール」「ID発行・ステータス」「参加承認・参加者」という実態と乖離した4つの入口は廃止し、1つの市場につき遷移先は「コントロールルーム」1つだけという事実をナビにそのまま反映する。「情報照会端末」は未実装のため非表示にする。

#### 生徒側サイトマップ

```
/join                     参加コード入力（変更なし）
/markets/:id/play         市場画面（フェーズに応じて中身が変わる: 初回説明→取引→結果）
```

ルーティングは現状維持。

### 2. コントロールルームの詳細設計

#### 常時表示（タブの外、ヘッダー直下に固定）

市場フェーズを常時表示する帯を新設する。

```
[ 準備中 ] → [ 取引中 ] → [ 結果を確定中 ] → [ 終了 ]
        現在地点をハイライト表示。経過時間・参加者数(●/定員)もここに集約する。
```

現行 `HostStatusPanel` の「経過時間」「参加者」「未処理の注文」はこの帯に統合する。価格テーブルは「進行操作」タブに残す。「緊急暴落」「緊急急騰」ボタンと「詳細」リンクは未実装の飾りのため削除する（将来実装する場合は、機能実装時にあらためて設計する）。

#### タブ構成

1. **参加受付**（デフォルトタブ。`SETUP` 状態で開いた場合はここが初期表示）
   - 参加コード／マジックリンク、承認待ちリスト、参加中リスト、チーム編成モード。中身は既存 `AdmissionPanel` をそのまま流用する。
2. **進行操作**
   - ホスト取得ボタン、市場開始/終了ボタン、価格テーブル（`HostStatusPanel` の実データ部分のみ）。
3. **ニュース配信**
   - 現行のManual Newsカードをそのまま。
4. **教室画面**
   - サイネージの説明と「別タブで開く」ボタン。埋め込みはせず、プロジェクターに繋いだ別端末で開く現行運用を維持する。

#### ダッシュボードとの役割分担（重複解消）

- 「市場の管理」ページ（`/teacher/markets`）は、市場を作る・選ぶ・削除する・結果CSVを取得する場所に限定する。参加受付UIはここから撤去し、「参加を受け付ける」ボタンでコントロールルームの参加受付タブへ誘導するだけにする。
- 参加者操作（承認・却下・チーム再割当・退出）は常にコントロールルーム1箇所に一本化する。

#### 進行の自動誘導

市場のステータスに応じて、コントロールルームを開いた際の初期タブを自動選択する。

- `SETUP` → 参加受付タブ
- `OPEN` → 進行操作タブ
- `ENDING`/`ENDED` → 進行操作タブ（結果確定の案内を表示）

タブ選択状態はURLクエリ（例 `?tab=news`）に保持し、リロード後も同じタブに戻れるようにする。

### 3. 生徒側フローの設計

#### 初回説明（オンボーディング）

参加承認後、市場画面に初めて入ったタイミングで、画面内に埋め込み型の説明カードを表示する（モーダルではない）。閉じたら `localStorage`（例 `stock-league:student-onboarding:${uid}`）にフラグを立て、次回以降は表示しない。

内容:

```
このチームでの投資について
・現金と株は「チーム」で共有します（あなた一人の持ち物ではありません）
・銘柄を選んで、買う/売るを選択します
・価格は毎秒動きます。ニュースで大きく動くこともあります
・終了後にチームの順位と結果が見られます
                                    [わかった → 取引を始める]
```

「チームで資産を共有している」という前提を、取引を始める前に提示する。これが今回の核心的な変更点であり、個人の判断で売買して後から混乱するという失敗パターンを防ぐ。

#### フェーズ表示の統一

生徒側ヘッダーのステータスチップを、教師側と同じ日本語ラベルに統一する（`OPEN`→取引中、`CONNECTING`→接続中、など）。

#### 復帰コードの扱いを控えめに

現状はポートフォリオカードに常時大きく表示している。変更後は、通常時はヘッダー内の補助メニューに折りたたみ、「別の端末で続きから参加したいとき」という一言の説明を添える。目立たせるのは、実際に接続が切れた場面や、復帰コードの入力が必要な参加画面のみとする。

#### 取引画面自体

`TradePanel` の操作フロー（数量入力→確認→送信）自体は既に分かりやすい作りのため大きくは変えない。「買える数/売れる数」表示は維持する。

### 4. 用語・表記の統一方針

| 対象 | 現状 | 変更後 |
|---|---|---|
| 市場フェーズ | 教師側「準備中/取引中/結果を確定中/終了」、生徒側は英語混在（`OPEN`, `CONNECTING`） | 両者で同じ日本語ラベルに統一する |
| ホスト操作の専門用語 | 「ホストリース」「リースが失効」などシステム内部用語がそのまま露出 | ユーザー向け文言は「この端末で進行を担当する」「進行がほかの端末に移った」のように行為ベースに言い換える。「リース」は内部実装用語としてコードにのみ残す |
| ナビラベル | 実態と乖離した機能名（シナリオ・ニュース予約、MCコントロール等） | 実際の遷移先ベースのラベル（コントロールルーム、参加受付 等） |
| 未実装機能 | 常時disabledで理由不明 | 非表示にする。将来実装が確定した時点で「近日公開」バッジ付きで表示する |

### 5. 技術面・移行時の注意点

- **ルート変更**: `/teacher/markets/:id/host` → `/teacher/markets/:id/room`。旧URLは `Navigate replace` によるリダイレクトを追加し、共有済みリンクやブックマークを壊さない。
- **AdmissionPanelの単一化**: `MarketDashboard.tsx` 側の重複呼び出しを削除し、コントロールルームのタブ内実装（現 `HostConsole` 内）に一本化する。データフロー（`approveJoinRequest` 等のハンドラ）はコントロールルーム側に既に存在するため、削除のみで機能追加は不要。
- **HostStatusPanelの縮小**: 飾りボタンを削除し、価格テーブルと経過時間表示のみ残す。既存テストへの影響範囲を実装計画時に確認する。
- **タブ状態の永続化**: コントロールルームのタブ選択をURLクエリに載せる。
- **生徒オンボーディングの表示制御**: 教師の `OnboardingWizard` と同様、`localStorage` キーで一度見たら次回から出さない方式に揃える。

## 対象外（今回のスコープに含めない）

- 「緊急暴落」「緊急急騰」機能そのものの実装（未定のため、今回は削除のみ）。
- 「情報照会端末」機能そのものの実装（今回は非表示化のみ）。
- サイネージ画面の埋め込み表示化（別タブで開く現行運用を維持）。
- 生徒画面のビジュアルデザイン全面刷新（オンボーディングカードと表記統一のみ）。
