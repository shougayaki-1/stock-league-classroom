# 管理画面ワークスペース化・第1弾（シェル刷新＋銘柄一時停止編集）

## 背景・課題

教師が admin 画面（フロー・UI）を、参考プロジェクト `../kaisei-stock-league` の管理画面に近い構成へ作り直したいという要望。kaisei は単一市場・グローバル運用型で、サイドメニュー＋複数ページ（銘柄制御・シナリオ予約・ニュースプリセット・MCコントロール・サイネージ管理）という構成を持つ。一方 `stock-league-classroom` は元々マルチテナント型（教師が複数の「市場」を作成し、生徒が参加コードで参加する）であり、[2026-08-04-teacher-student-ux-navigation-design.md](./2026-08-04-teacher-student-ux-navigation-design.md) によって直近、コントロールルーム（`/teacher/markets/:id/room`、タブ：参加受付／進行操作／ニュース配信／教室画面）に整理された。

今回の要望は、この上にさらに次を載せる大掛かりな再設計であることが判明した。

1. 市場選択を Slack のワークスペース選択のような「箱を選ぶ／作る」画面にする
2. 市場設定（銘柄／ニュースプリセット作成／ニュース設定）をサイドメニュー化する
3. `/admin/mc/` 的な進行用タブ画面（現状の参加受付等で可）
4. kaisei の `/scenario/` サイネージを教室画面として移植し、進行タブに MC サイネージ操作ボタンを追加する

加えて、現在の UI（教師・生徒問わずサービス全体）に対する強い不満（MUI移行の未完了、AI生成っぽい見た目、狭い画面でのボタン崩れ・はみ出し）があり、保守性向上のためのコンポーネント化も同時に求められている。

この一式は 1 つの実装計画に収めるには大きすぎるため、5 つのサブプロジェクトに分解した。本ドキュメントは **サブプロジェクト1（管理画面シェル刷新）** のみを設計対象とする。

### 全体の分解（参考・詳細設計は各着手時に行う）

1. **管理画面シェルの刷新**（本ドキュメントの対象）— ワークスペース風の市場選択画面＋サイドメニュー付きレイアウトの器
2. **ニュースプリセット管理**（未着手）— 見出し・本文・演出のテンプレートをCRUD管理
3. **シナリオ予約**（未着手）— プリセットを使い時刻指定でニュース＋価格イベントを予約し自動/手動発火
4. **MC進行タブの整理**（未着手）— 既存コントロールルームのタブ構成を新シェル配下に再編（中身はほぼ現状維持）
5. **教室サイネージ移植**（未着手）— kaisei の公開サイネージ（銘柄グリッド・ニュース・ランキング等）を移植し、進行タブに MC サイネージ操作ボタンを追加

UI 統一は「今回さわる画面から新デザインシステムに置き換え、最後に未対応画面をまとめて回収する」段階的な方針で進める（生徒側含むサービス全体が最終的な対象）。

### 別トラック（本ドキュメントの対象外）

「ホストの取得ができません」というエラー報告は、今回のUI変更とは別に不具合調査タスクとして扱う。

## スコープ・前提

- 本ドキュメントはサブプロジェクト1のみを設計する。ニュースプリセット・シナリオ予約・サイネージ本体の実装は対象外。
- 既存の Firebase リアルタイム同期アーキテクチャ（ホストリース、RTDB リスナー等）は壊さない。
- 主要URLの互換性は維持する（`/teacher/markets`, `/teacher/markets/:id/room` は変更しない）。
- UI ライブラリは引き続き MUI。今回新規・再構築するコンポーネントは MUI ベースで統一し、旧来の生 CSS クラス（`className="teacher-*"` 等）は使わない。

## 設計

### 1. 発見事項：`PAUSED` は実装済みの死んだ状態

調査の結果、`MarketStatus` 型に `PAUSED` が定義され、再開ロジック（`openMarket` の PAUSED 分岐、一時停止中の経過時間を凍結する処理）も実装済みだが、**`meta.status` を `PAUSED` に遷移させる処理がコードベースのどこにも存在しない**（`grep` で確認済み）。生徒側・教師側の UI 表示分岐（`canResume`, `isPaused`, `StudentMarketPage` の一時停止バナー等）はすべて存在するが、到達不能である。

これは「手動一時停止」機能の土台が未完成のまま残されたものと判断できる。今回の「一時停止して銘柄編集→再開」要望は、この空所を埋める形で実装する。

### 2. IA・ルーティング

- `/teacher/markets` を **ワークスペース選択画面** に刷新する。
  - 教師が所有する市場をカード一覧表示（タイトル・状態チップ・参加コード・接続中人数）。
  - 「＋ 新しい授業を作る」操作で、既存の作成フォーム（テンプレート選択・公開範囲）をインライン展開する。ロジックは既存 `createMarket` フローを流用し、UI のみ刷新する。
  - 市場を選ぶと、既存の `/teacher/markets/:marketId/room` へ遷移する（変更なし）。
- 新規ルート `/teacher/markets/:marketId/stocks` を追加する（銘柄編集画面）。
- `/templates` は変更しない（引き続き「テンプレートを編集」の遷移先）。

### 3. 新 `AdminShell`（`TeacherShell` を置き換え）

- `TeacherShell` の責務（ブランド表示・サイドナビ・アカウントフッター）を引き継ぎつつ、次を目的に作り直す。
  - レスポンシブ対応：狭い画面でボタン列が崩れる／はみ出す現行の不具合を解消する。
  - 生CSSクラス依存を排除し、MUI の `sx` とテーマトークンのみで構成する。
- サイドバー構成：

  ```
  市場設定
    └ 銘柄 (/teacher/markets/:id/stocks)
  この市場を進行する
    └ 進行 (/teacher/markets/:id/room)   ← 既存コントロールルーム、タブ構成は変更なし
    └ 教室画面 (/markets/:id/signage)
  サポート
    └ 使い方を見る
  ```

  「ニュースプリセット」「ニュース設定（シナリオ）」は、サブプロジェクト2・3が実装されるまでサイドバーに追加しない（未実装のメニュー項目を露出させない）。

- 市場を選んでいない状態（ワークスペース選択画面）では `AdminShell` を使わない。

### 4. 新機能：市場の一時停止 → 銘柄編集 → 再開

- `src/lib/market/hostTrading.ts` に `pauseMarket` を追加する。
  - `OPEN` かつ有効なリース保有時のみ `PAUSED` へ遷移し、`meta.pausedAtMillis` を設定する。
  - 再開時の処理（`openMarket` の PAUSED 分岐）は既存のまま利用できる（経過時間の凍結ロジックは実装済み）。
- `src/lib/market/hostTrading.ts` に `updateMarketCompanies` を追加する。
  - 許可される状態は `SETUP` と `PAUSED` のみ。`OPEN`/`ENDING`/`ENDED` では拒否する。
  - `liveMarkets/{marketId}/companies` の各エントリ（`name`, `symbol`, `basePrice`, `phases`）を更新する。
  - バリデーションは既存のテンプレート検証（`templateValidation.ts`）と同等のルールを適用する。
- `MarketControlPanel` に「市場を一時停止」ボタンを追加する（`OPEN` 時のみ表示、既存の「市場を終了」ボタンとは別のアクション）。案内文言で「銘柄を編集する場合はこちら」であることを明示する。
- 新規 `/teacher/markets/:marketId/stocks` 画面：
  - 現在の市場の銘柄一覧（社名・シンボル・基準価格・価格フェーズ）を表示する。
  - `SETUP` / `PAUSED` 時：編集可能（保存で `updateMarketCompanies` を呼ぶ）。
  - `OPEN` / `ENDING` / `ENDED` 時：読み取り専用表示＋「編集するには市場を一時停止してください」の案内バナー（`OPEN` の場合はその場で一時停止できるボタンも表示）。

### 5. コンポーネント化（デザインシステムの土台）

- `AdminShell`（サイドバーレイアウト）、レスポンシブに折り返す共通アクションボタン列、`SectionCard`（見出し＋説明＋本文のカードパターン）を新規に切り出し、以降のサブプロジェクトおよび今後さわる生徒側画面でも再利用する。
- 肥大化した `MarketDashboard.tsx`（教師用ダッシュボードと生徒参加フォームが同居）を分割する。
  - `WorkspacePicker.tsx`（新規、教師のワークスペース選択・作成）
  - `StudentMarketJoin.tsx`（既存ロジックを移動。ファイルを触るついでに `className="portal-*"` 等の旧CSSクラスも `sx` に置き換える）
- `TemplateWorkspace` の価格フェーズ編集 UI を共有コンポーネント `PricePhaseEditor` として切り出し、テンプレート編集画面と新しい銘柄編集画面の両方で使う。
- 置き換えにより不要になった `App.css` / `index.css` 内の旧CSSクラス（`.teacher-*`, `.market-picker-*`, `.create-market-card`, `.active-market-card`, `.portal-*` 等）を削除する。

### 6. エラーハンドリング

- `pauseMarket` / `updateMarketCompanies` の失敗（リース喪失・権限なし等）は、既存の `handleFailure` パターンに沿ってコントロールルームの `notice` 表示に統一する。
- 銘柄編集画面での状態不一致（例：編集中に生徒側の操作で市場が再開されるような競合はない設計だが、他端末が同時にホストを取得した場合のリース失効）は、既存の `ownsLiveLease` チェックに委ねる（新規の考慮は不要）。

### 7. テスト

- `hostTrading.test.ts` に `pauseMarket` / `updateMarketCompanies` のケースを追加する（既存のトランザクションテストパターンに合わせる）。
- `AdminShell`, `WorkspacePicker`, 新規銘柄編集画面、更新後の `MarketControlPanel.test.tsx` に対する RTL テストを追加・更新する。

## 対象外（今回のサブプロジェクト1に含めない）

- ニュースプリセット管理・シナリオ予約（サブプロジェクト2・3）
- MC進行タブの再編そのもの（サブプロジェクト4。今回はサイドバーの遷移先として維持するのみ）
- 教室サイネージの kaisei からの移植（サブプロジェクト5）
- 生徒側画面の全面刷新（今回touchする `StudentMarketJoin` の旧CSS除去のみ実施し、それ以外は対象外）
- 「ホストの取得ができません」不具合の調査・修正（別タスク）
